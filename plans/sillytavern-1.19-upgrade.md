## Как устроены расширения и этот проект

UI-расширения SillyTavern выполняются в браузере. Manifest задаёт JS/CSS, порядок загрузки, зависимости, минимальную версию клиента и необязательный generation interceptor. Основная точка интеграции — `SillyTavern.getContext()`: состояние чата, события, генерация, настройки и сохранение. Серверные плагины — отдельный механизм; для ScenePulseN собственный серверный плагин не требуется. [Официальное руководство](https://docs.sillytavern.app/for-contributors/writing-extensions/).

У ScenePulseN:

- `manifest.json` подключает `index.js`, `style.css` и `scenePulseInterceptor`; минимум — 1.18.0.
- `index.js` связывает APP_READY, генерацию, streaming, редактирование, смену чата, свайпы, удаление и события World Info. При старте создаются панель, настройки, команды, макросы и диагностика.
- `src/settings.js` хранит глобальные настройки через extensionSettings, а снимки и настройки конкретного чата — через `chatMetadata.scenepulse`. `src/profiles.js` управляет профилями схемы и промпта. Это другой вид профилей, чем Connection Manager.
- **Together:** interceptor строит план вставок промпта → основная модель выдаёт повествование и tracker → извлечение и нормализация → сохранение снимка → обновление панели. При доступном MessageFormatter tracker скрывается синхронным hook до regex; на 1.18 остаются regex и streaming hider. Извлечение отдельно очищает текст и сохраняет снимок; formatter не меняет сообщения.
- **Separate:** из выбранных сообщений и предыдущего состояния формируется отдельный запрос. `request.js` предпочитает `generateRawData`, затем `generateRaw`, затем quiet fallback. Native уже передаёт JSON schema; это не новая функция предлагаемого обновления.
- **Параллельный Separate:** Core определяет сцену и состав NPC, отдельные запросы извлекают персонажей, Global — общие данные; `parallel-build.js` объединяет результат. `profile-request.js` уже использует `ConnectionManagerRequestService`, не переключая глобальный профиль.
- `message-fingerprint.js` проверяет владельца операции: чат, сообщение, свайп и отпечатки текста. `settings.js` содержит снимки по свайпам и обработку устаревания; wiki сохраняет архив персонажей.
- Контекст описывает установленное состояние, не заставляет сюжет следовать прогнозу. Не включать в модернизацию автоматическое продвижение планов NPC или навязывание действий.

Ключевой поток: **событие ST → зафиксированные настройки/схема/владелец → генерация → извлечение → проверка → объединение состояния → проверка владельца → сохранение → UI**.

## Что изменилось относительно 1.18

| Изменение в 1.19 | Значение для ScenePulseN |
| --- | --- |
| MessageFormatter: обработка до regex, после regex и после Markdown | Возможность скрывать служебный tracker до попадания в DOM |
| `/addswipe` больше не перезагружает чат целиком | Проверить обновление снимков и UI по событиям свайпа без CHAT_CHANGED |
| Исправлено переключение источника Chat Completion при смене профиля | Проверить обычный Separate и fallback между разными провайдерами |
| Новые integrity identifiers у веток/checkpoints; удаление связанных tool-call сообщений | Проверить принадлежность снимков и смещения индексов |
| Переименование lorebook обновляет связи с чатами, персонажами и персонами | Проверить Scene Source Trace, где ключ включает имя world |
| Расширены макросы; изменена обработка scoped comments | Регрессии пользовательских промптов и альтернативных tracker-маркеров |
| Новые модели и настройки reasoning; изменения custom request macros | Аудит пресетов и поведения выбранного transport |
| Улучшены ошибки провайдеров, сохранение повреждённых чатов и серверная защита | Польза обновления ядра; не нужно дублировать эти исправления в расширении |

Обзор основан на [release notes](https://github.com/SillyTavern/SillyTavern/releases/tag/1.19.0). Профильные запросы и structured output уже используются проектом; не считать их нововведениями 1.19.
